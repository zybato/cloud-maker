# Cloud Maker

Решение задания по запуску и управлению виртуальными машинами на Linux-хосте с помощью QEMU/KVM.

## Реализованные пункты

- Базовое задание: запуск ВМ через QEMU (CLI), автоматическая проверка SSH-доступа.
- Доп. задание №1: HTTP API для управления ВМ (Flask): создание, остановка, удаление, статус.
- Доп. задание №2: настройка через cloud-init: пользователь, SSH-ключ, hostname.
- Доп. задание №9: квоты — запрет создания ВМ при превышении лимитов RAM/CPU.
- Доп. задание №10: простой веб-интерфейс поверх API.
- Доп. задание №11: скрипт автоматической проверки (check.sh).
- Доп. задание №12: скрипт очистки (cleanup.sh).

## Как это работает

1. run.sh скачивает официальный облачный образ Ubuntu 24.04 (noble-server-cloudimg-amd64.img), если его ещё нет.
2. При первом запуске генерируется SSH-ключ vm_key (у каждого запускающего — свой).
3. Публичный ключ подставляется в шаблон user-data.tpl.yaml, создаётся meta-data.yaml.
   Утилита cloud-localds упаковывает их в образ seed.img, который подключается к ВМ как второй диск.
   При загрузке cloud-init внутри ВМ находит этот диск, создаёт пользователя student
   с sudo без пароля, добавляет ему SSH-ключ и задаёт hostname cloud-maker-vm.
4. QEMU запускает ВМ:
   - -accel kvm — аппаратная виртуализация, если доступен /dev/kvm;
     иначе автоматически используется программная эмуляция -accel tcg (медленнее);
   - -m / -smp — объём памяти и число ядер (параметры run.sh);
   - -drive ... if=virtio — системный диск и диск cloud-init;
   - -netdev user,hostfwd=tcp::2222-:22 — сеть ВМ через NAT, порт 2222 хоста
     пробрасывается на SSH (22) внутри ВМ.
5. При запуске из терминала консоль ВМ выводится в терминал (-nographic).
   При запуске в фоне (из check.sh) консоль пишется в файл vm-console.log.

## Зависимости (Debian/Ubuntu)

sudo apt install -y qemu-system-x86 qemu-utils cloud-image-utils wget openssh-client python3-venv

Для аппаратного ускорения пользователю нужен доступ к /dev/kvm:

sudo usermod -aG kvm $USER   # затем перелогиниться

Если KVM недоступен (например, хост сам является ВМ без вложенной виртуализации),
run.sh автоматически переключается на эмуляцию TCG — загрузка ВМ займёт несколько минут.

## Структура проекта

- run.sh — запуск ВМ: ./run.sh [RAM_MB] [CPU], по умолчанию 2048 MB и 2 CPU.
- check.sh — автоматическая проверка.
- cleanup.sh — остановка QEMU и удаление временных файлов.
- api.py — Flask-сервер для управления ВМ.
- templates/index.html — веб-интерфейс.
- user-data.tpl.yaml — шаблон cloud-init (SSH-ключ подставляется в run.sh).
- requirements.txt — зависимости Python.

## Как проверить решение

### 1. Автоматическая проверка

chmod +x run.sh check.sh cleanup.sh
./check.sh

Скрипт запускает ВМ, ждёт загрузки (до ~10 минут при эмуляции TCG), подключается по SSH
с помощью сгенерированного ключа, проверяет, что cloud-init задал hostname,
после чего останавливает ВМ.

Ожидаемый результат:

✅ УСПЕХ: ВМ запущена, SSH доступен по ключу, cloud-init задал hostname: cloud-maker-vm

Если при эмуляции TCG ядро ВМ падает при старте (Kernel panic), скрипт автоматически
перезапускает ВМ (до 3 попыток). Лог QEMU — vm.log, консоль ВМ — vm-console.log.

### 2. Ручной запуск и вход в ВМ

./run.sh

В другом терминале:

ssh -i vm_key -p 2222 student@127.0.0.1

Выйти из консоли QEMU: Ctrl+A, затем X.

### 3. API и веб-интерфейс

python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
python3 api.py

Откройте http://127.0.0.1:5000.

1. Нажмите «Создать ВМ» и дождитесь статуса «ЗАПУЩЕНА». Через несколько минут к ВМ можно подключиться по SSH (см. п. 2).
2. Введите CPU = 4 и нажмите «Создать ВМ» — должна появиться ошибка Quota exceeded.
3. Нажмите «Остановить».

API можно вызывать и напрямую:

curl -X POST "http://127.0.0.1:5000/create?ram=2048&cpu=1"
curl http://127.0.0.1:5000/status
curl -X POST http://127.0.0.1:5000/stop
curl -X POST http://127.0.0.1:5000/delete

### 4. Очистка

./cleanup.sh
Останавливает QEMU и удаляет временные файлы (seed.img, логи, сгенерированные ключ и конфиги cloud-init).
Базовый образ Ubuntu не удаляется, чтобы не скачивать его заново.
